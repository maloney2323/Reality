# Reality: Foundational Generation & Isolated Sandbox v1

## Constitutional placement

The Reality Governed Self-Improvement Spine owns the source-linked goal, permissions, lifecycle, registry and final settlement. This package supplies the replaceable **cognition and verification machinery** used by that spine, not an alternative constitutional authority.

Real architecture:

1. Independently read the owner GoalState, source message, original work, observed gap, base commit and frozen regression manifest into a pinned **Build Ticket**. Never build a ticket solely from text generated by a model or a browser.
2. Invoke a replaceable model through the proposal-only **Model Generator**. Require an exact ticket hash, original work identity, extension-only source and model-written tests.
3. Give the candidate to a different no-secret **Docker Sandbox**. The sandbox requires a digest-pinned container, no network, no capabilities, nonroot, read-only checkout, CPU/memory/time limits and frozen tests run separately from model tests. A candidate may not overwrite existing repo files.
4. Check the sandbox runner receipt and exact artifact SHA against an **independent provider readback**. Raw JSON saying 'passed' is never accepted.
5. Record every attempt in durable **Continuity**, and independently read back the exact receipt before another model call.
6. Only syntax or tested code regressions receive automatic repair. Missing dependency or missing owner authority escalate with evidence; retry budget is finite and model-independent.
7. A sandbox pass stops at **AWAITING_EXACT_OWNER_APPROVAL**. The existing constitutional spine alone governs promotion/registration, original-work continuation, final settlement and cross-world consequences.

## Implemented in this change

- src/reality-foundational-build-loop-v1.0.js: typed ticket, immutable goal/work scope, candidate hashing, report normalization, provider readback, bounded model correction and durable-checkpoint contract.
- src/reality-foundational-model-provider-v1.0.js: replaceable OpenAI Responses generator; model output is untrusted source and never a receipt.
- src/reality-foundational-constitutional-adapters-v1.0.js: a typed bridge into the EXISTING governed self-improvement driver. Its `generateCandidate` and `runIsolatedSandbox` methods preserve the original work and canonical constitutional artifact hash, while rechecking provider evidence. No duplicate authority or independent promotion controller is introduced.
- src/reality-foundational-sandbox-adapter-v1.0.js: a real no-secret Docker invocation adapter. A digest-pinned Node image and independently frozen suite are mandatory. Docker is injected in tests, but it must run on a real isolated runner in operations.
- test/reality-foundational-build-loop-v1.0.test.js: adversarial contract tests, including actual Docker command-line assertions, independent readback and no false installation.

## Integration that remains necessary

The existing constitutional driver can now consume the new foundational `generateCandidate` and `runIsolatedSandbox` adapters. The current trusted owner chat readback identifies work but **does not issue an independently attested Build Ticket**. A real automation worker still has to supply the pinned ticket and perform model generation in a secret-bearing process isolated from the *separate* no-secret sandbox worker. The independent provider receipt and Continuity append/readback adapters must connect to the canonical constitutional driver, not to a second approval system. Use a controlled GitHub Action or an equivalently isolated runner with immutable artifact transfer and zero sandbox secrets. A model response may never choose the trusted adapter, artifact referee, command to execute, frozen test paths, or owner authorization.

**Important security:** This architecture rejects source that modifies the core, API, authentication or persistence. Governance-kernel upgrades use a separate explicitly authorized release process; a model must not rewrite the component that verifies its own permissions. Sandboxing constrains risk; it does not mathematically guarantee safety, eliminate hallucination or make an LLM superintelligent.

## Acceptance test

A real owner goal and actual unfinished job, such as original Reality #143, must produce independently verified source evidence, a model-authored upgrade, real no-secret sandbox tests with frozen regressions, recorded automatic corrections, and a source-bound candidate awaiting separate owner approval. The same original job resumes and settles only after the existing constitutional authorization and registry readback. Zero production effects and no claimed historical repair if the fix was already present.

**Status of this PR:** model-neutral core, replaceable provider, Docker adapter, local/CI adversarial tests. **Not yet** a live chat-triggered autonomous engineer, not an installed capability, and not a proven 7/7 original job.

The sandbox refuses mutable checkouts: the independent runner must prove its Git HEAD exactly matches the ticket's verified 40-character base commit before any candidate code enters Docker.
