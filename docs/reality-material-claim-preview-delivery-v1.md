# Reality Material Claim Verification — Preview Pre-Delivery Integration

## Status
Integrated into the real authenticated standalone endpoint's response path (`api/reality/standalone-chat.js` → `processCausalTurn` → `processStandaloneChat`) as an **opt-in Preview feature**. Not enabled by default, not merged into `master`, not deployed to the live customer environment.

## Position in the causal pipeline
1. Authenticated customer message stored and checked, owner-scoped history restored.
2. Original real model answer generated by Reality cognition.
3. Current provenance and continuity checks complete.
4. **New:** Preview-only post-model material claim check executes before `AUTHENTICATED_CONVERSATION_MESSAGE` assistant record is published. It reads owner-scoped, bitemporal `MATERIAL_EVIDENCE_ASSERTED` and `MATERIAL_EVIDENCE_REVOKED` rows.
5. The material claim verifier checks a narrow, explicit assertion in the original body against separately attested source evidence. It durably writes and reads back a `MATERIAL_CLAIM_AUDIT` receipt before delivery.
6. If a **separately attested contradiction** is found, the known-false explanation is withheld from the **displayed** answer and replaced by a provenance-scoped, non-executing notice. The original model answer remains stored unchanged for audit and drift metrics.
7. If attestation is missing or coverage is incomplete, the answer remains unchanged rather than being presented as "verified" or rewritten on speculative grounds.
8. The existing causal turn commit still links original model text, the actual displayed message, and read-back receipts. No external business action is performed.

## Feature flag and critical security preconditions
`REALITY_STANDALONE_MATERIAL_VERIFIER_ENABLED=true` is a **server-side Preview-only flag**, never a caller payload property. The authenticated standalone pilot also requires `REALITY_STANDALONE_CHAT_ENABLED=true`, durability, valid Supabase provider authentication, and exact preview-project binding; it refuses production releases.

**IMPORTANT:** The default `materialSourceAttestor` is an explicit **deny-all**. Simply toggling the flag does **NOT** supply authenticated source truth or enable reliable false-claim blocking. The provider-owned server process must separately supply an independently authenticated, permission-scoped source attestation implementation. It must bind source reference, entry identity, hash, source identity and contemporaneous evidence receipt and must not trust user/model assertions or a ledger SHA by itself.

The current automatic extraction is intentionally limited to explicit unquoted inspection status statements with a supported job ID in the same clause. It does not claim whole-answer material claim coverage. Drafts, quoted supplier claims, and questions remain useful without a fabricated correction.

The finite 300-row scan refuses to claim complete evidence coverage if it hits the cap. No cache invalidation, paging to exhaustion, signed real municipal data ingestion, payment execution or model-driven learning is implemented.

## Experimental proof
[GitHub Actions material-claim and standalone regression gate](https://github.com/maloney2323/Reality/actions/runs/40097472143): **112/112 passed, zero paid model calls.**

- Replays the **authentic Turn 79 false sentence** captured from the prior 120-turn live GPT-4.1-mini experiment.
- Exercises `processStandaloneChat`, not just a direct verifier call.
- Verifies contradiction is withheld from display *before* the authenticated assistant message is stored.
- Verifies the original model text is preserved separately from the customer-visible text.
- Verifies independently attested sources, future-effective supersession, other-job isolation, and denied attestors.
- Verifies ordinary draft answers and supported current-PASS responses are not overcorrected.
- Verifies a `MATERIAL_CLAIM_AUDIT` receipt is append-only and independently read back.

These tests use a mocked authenticated source adapter and historical genuine model text. They do **not** prove the same gate is currently stopping drift in a live customer session or that the independent source-authentication service is available.

## Promotion gates
- Source attestor verified against a live third-party provider with identity, scope, valid time, and signed/attested retrieval.
- Material claim extractor with measured recall, negation, quote handling, multi-source and cross-job isolation; **unknown coverage never certified as complete**.
- Preview authenticated end-to-end test using a *new live model response* and source readbacks, then blinded review of both false-positive and false-negative cases.
- True durability and post-delivery audit visibility in UI.
- Separate human authorization for all consequential actions; no automatic deployment or approval inferred from model output.

The design deliberately improves epistemic checking, not model prompt strength, and records the difference between original underlying-model drift and Reality's corrective contribution.
